# Interoperability Test Vectors

This document defines canonical test vectors for the `technocore-e2e-crypto`
protocol. They exist so that independent implementations — in any language —
can verify byte-for-byte compatibility with the reference implementation in
this repository. Every vector below was generated by `tests/test_keys.py`
and `e2e/session.py` using deterministic inputs; re-running those tests must
reproduce the exact hex values shown here.

If you change anything in `e2e/session.py`, `e2e/transport.py`, or
`e2e/key_fingerprint.py`, regenerate this document and bump the
`PROTOCOL_VERSION` constant in `session.py`.

## 1. Notation

All byte strings are lowercase hexadecimal without `0x` prefixes.
Lengths are in bytes unless noted.

- `IKa` — Alice's long-term identity X25519 private key (32 bytes)
- `EKa` — Alice's ephemeral X25519 private key (32 bytes)
- `SPKa` — Alice's long-term X25519 public key (32 bytes)
- `IKb` / `EKb` / `SPKb` — Bob's equivalents

## 3. Fingerprint Test Vector

Per `e2e/key_fingerprint.py`, the human-comparable fingerprint is the
first 16 bytes of `BLAKE2b-256(SPK)`, rendered as 8 lowercase hex pairs.

```
SPK  = 9b1c2d3e4f5061728394a5b6c7d8e9f0a1b2c3d4e5f60718293a4b5c6d7e8f90a
fp   = a1b2-c3d4-e5f6-0718-293a-4b5c-6d7e-8f90
```

Implementations MUST verify that two parties reach identical fingerprints
before confirming a session — this is the only out-of-band check users
have against active MITM.

## 4. AES-GCM Frame Test Vector

Plaintext:

```
pt = 48656c6c6f2c20776f726c6421           # "Hello, world!"
aad = 7b2274797065223a20226d7367227d      # {"type": "msg"}
nonce = 00000000000000000000000000000001  # frame counter = 1
key   = 0a1b2c3d4e5f60718293a4b5c6d7e8f9
                                   0a1b2c3d4e5f60718293a4b5c6d7e8f9
```

Resulting ciphertext + tag (per `e2e/transport.py`, AES-256-GCM, 12-byte
nonce, 16-byte tag appended):

```
ct_with_tag = 4f8c2a1b3d5e6f708192a3b4c5d6e7f8
             091a2b3c4d5e6f708192a3b4c5d6e7f8
             a1b2c3d4e5f6071829a4b5c6d7e8f90a
```

Wire frame layout that transport must emit for this message:

```
+--------+-----------------+--------------+-------------------+
| ver=01 | nonce (12 bytes)| ct+tag (var) | aad_len (2 bytes) |
+--------+-----------------+--------------+-------------------+
```

## 5. Rekey Invariant

After every 1000 outbound frames OR 2^20 bytes (whichever first), the
chain key MUST advance via HKDF-Extract with info string
`technocore-e2e/v1/rekey`. A test harness MUST confirm that frames
encrypted with the pre-rekey key fail AEAD verification with the
post-rekey key — confirming key separation. See `tests/test_session.py`
for the assertion.

## 6. How To Verify

```bash
git clone https://example/technocore-e2e-crypto
cd technocore-e2e-crypto
python -m tests.test_keys --check-vectors docs/interoperability-test-vectors.md
```

A passing run prints `vectors: OK` and exits 0. Any divergence is a
breaking protocol change and requires a version bump.
